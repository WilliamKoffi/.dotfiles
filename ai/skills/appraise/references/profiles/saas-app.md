# Profile — SaaS or web application behind a login

**Extra personas:** Customer Success Lead, Data & Privacy Officer. Add the SEO Specialist only
for the public pages (landing, pricing, docs); the screens behind the login are `N/A` for SEO.

## P1. Onboarding
Sign-up, invitation, first login, email or phone verification, the empty first screen, the
time to the first useful result, password reset.

## P2. Roles & permissions
Each role sees and does only what it should, in the UI and in the API; an action the role
lacks is hidden, not offered then refused; a role change takes effect without a re-login.

## P3. Core workflows
The product's main tasks done many times a day: speed, keyboard use, bulk actions,
undo or confirmation on destructive actions, state kept across reloads.

## P4. Errors & resilience
Every refused request shows a message a person understands; offline and slow network;
session expiry; no screen that halts the whole app.

## P5. Data ownership
Export, deletion, audit log, multi-tenant isolation, backups.

## P6. Support & observability
Error tracking, logs tied to a user and a request, an in-app way to get help, status page.

## Executive-summary questions
- Can a new customer reach value without help on day one?
- What would generate the first support tickets?
